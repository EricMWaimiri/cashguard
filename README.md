# CashGuard

**Know which payments to trust.** CashGuard is a fraud-risk copilot for small merchants. A machine-learning model scores each incoming order, an LLM explains the score in plain English, and the merchant captures or voids the held payment with one click. The money movement runs through the **PayPal sandbox**.

Built for the PayPal AI Hackathon by [Eric Mwangi](https://github.com/EricMWaimiri).

## The problem
Small merchants often face a bad choice with a suspicious order: ship it and risk a chargeback, or cancel it and risk losing a real customer. They usually see a number with no explanation, and they have no easy way to act on it.

## How it works
1. **Hold, don't take.** Orders are created with PayPal's `AUTHORIZE` intent, so the money is held but not captured.
2. **Score.** A logistic regression model estimates fraud risk from five order signals: amount, account age, billing/shipping mismatch, hour of day and orders in the last hour.
3. **Recommend.** Under 30% risk suggests CAPTURE, 30-70% suggests REVIEW, and 70% or more suggests VOID.
4. **Explain.** The model's top risk factors are passed to a Gemini model, which writes two short sentences for the merchant. The prompt allows only the listed factors, so the explanation cannot invent reasons the model did not use.
5. **Decide.** The merchant clicks *Approve capture* or *Void order*. Both buttons call the PayPal API and show the real response. The AI recommends; the human decides.

## PayPal APIs used
- Orders v2: create an order with `intent=AUTHORIZE`
- Orders v2: authorize an approved order
- Payments v2: capture an authorization
- Payments v2: void an authorization

## AI tools used
- **scikit-learn** (logistic regression) for fraud scoring, with per-order factor contributions (coefficient x difference from a typical order)
- **Google Gemini** (via the REST API) for plain-English explanations. The app tries several models in turn and saves each explanation once written. If no model responds, it falls back to a template explanation so the app keeps working.

## Run it yourself
You need Python 3.10+, a free [PayPal Developer](https://developer.paypal.com) account with a **sandbox** app (Client ID and Secret), a sandbox **Personal** (buyer) account, and a free Gemini API key from Google AI Studio.

```bash
git clone https://github.com/EricMWaimiri/cashguard.git
cd cashguard
pip install -r requirements.txt

# 1. Add your keys
cp .env.example .env        # on Windows: copy .env.example .env
# edit .env and fill in the three values

# 2. Generate the synthetic data and train the model
python gen_data.py
python train.py

# 3. Create three held PayPal orders (low, borderline and high risk)
python setup_orders.py
# Open each printed link in a private window, log in with your sandbox BUYER account,
# approve until you reach an example.com page, then press Enter in the terminal.

# 4. Start the app
streamlit run app.py
```

The dashboard shows three held orders. Capture or void them and check the result in your sandbox Business account at sandbox.paypal.com. Each order can be captured or voided only once; run `python setup_orders.py` again for a fresh set.

## Honest limitations
- **The model is trained on synthetic data** generated by `gen_data.py`. Its accuracy shows that it learned the rules built into that data, not that it detects real-world fraud.
- The three demo orders use hand-picked inputs so every outcome (capture, review, void) can be demonstrated.
- Everything runs in the PayPal **sandbox**. No real money moves.
